# Benchmark findings

When an experiment yields evidence relevant to improving Aspire, its skills,
or MCP usage, update `msbench/FINDINGS.md` in the same change as the experiment
report. Include negative/null findings and contradictions, not only wins.
Update an existing finding rather than duplicating the same lesson.

Keep full run tables and reproduction commands in the experiment README.
The findings register must link that evidence, separate observations from
improvement proposals, state limitations and implementation status, and
distinguish infrastructure failures, capability availability, actual tool use,
and verified conversation continuation.
